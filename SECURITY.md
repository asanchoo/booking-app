# Безопасность

## Поддерживаемая версия

Исправления безопасности применяются к актуальной версии ветки `main` и к опубликованной демонстрации.

## Как сообщить об уязвимости

Не публикуйте секреты, персональные данные клиентов или описание рабочей уязвимости в обычном GitHub Issue.

Используйте **GitHub → Security → Report a vulnerability**. В сообщении укажите:

- затронутый маршрут или экран;
- минимальные шаги воспроизведения;
- ожидаемое и фактическое поведение;
- возможное влияние;
- безопасный пример запроса без настоящих данных и ключей.

Если обнаружен опубликованный ключ, сначала отзовите и замените его у провайдера, затем удалите из окружений и истории Git. Простого удаления из последнего коммита недостаточно.

## Принципы проекта

- Секреты находятся только в серверных переменных окружения.
- Авторизация использует `HttpOnly`, `Secure` в production и `SameSite=Lax` cookies.
- Клиент, мастер и администратор защищены разными ролями и cookies.
- Внешняя AI-модель не получает контактные данные и не пишет напрямую в базу.
- Создание записи повторно проверяет услугу, мастера, слот и конфликт времени.
- Загрузки ограничены одним изображением до 5 МБ и проверяются по MIME и сигнатуре файла.
- API ограничивает размер JSON, частоту чувствительных операций и запрещает неизвестные origins.

Перед каждым релизом запускаются тесты, production-сборка, `npm audit` и проверка отслеживаемых файлов на секреты.
