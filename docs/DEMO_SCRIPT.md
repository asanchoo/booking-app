# Сценарий демонстрации проекта

Оптимальная продолжительность: 5–7 минут. Перед показом создайте отдельные демонстрационные аккаунты и не публикуйте их пароли в репозитории.

## 1. Проблема и результат — 30 секунд

«Это единая система записи для сервисного бизнеса. Клиент записывается без звонка, мастер работает со своим расписанием, администратор управляет операционной частью, а Telegram и AI уменьшают ручную работу».

## 2. Клиентский путь — 90 секунд

1. Открыть главную страницу на телефоне или в узком окне.
2. Выбрать услугу и обратить внимание, что показываются только подходящие мастера.
3. Выбрать реальный свободный слот.
4. Показать форму подтверждения и предложение подключить Telegram.
5. Открыть личный кабинет и показать перенос/отмену только собственной записи.

Не создавайте новую запись во время каждой демонстрации, если база используется публичными посетителями. Можно остановиться на экране подтверждения.

## 3. AI-помощник — 90 секунд

Пример запроса: «Хочу стрижку завтра после 16:00».

Показать, что помощник:

- использует реальные услуги;
- предлагает только мастеров выбранной услуги;
- возвращает только доступное время;
- просит явное подтверждение;
- не получает телефон до финального шага.

Если внешняя модель недоступна, объяснить детерминированный fallback как часть надёжности системы.

## 4. Кабинет мастера — 60 секунд

1. Показать только собственные записи мастера.
2. Отметить приход или отсутствие клиента.
3. Показать перерыв/недоступное время.
4. Показать отзывы и смену фотографии.

## 5. Админ-панель — 90 секунд

1. Обзор и ближайшие записи.
2. Календарь с переключателем мастеров на телефоне.
3. Создание услуги и назначение исполнителей.
4. Создание мастера с ролью и доступом в кабинет.
5. Настройки рабочих дней и часов.
6. Аналитика, отзывы и выгрузка списка.

## 6. Инженерная часть — 60 секунд

Показать README и коротко объяснить:

- React + Express;
- PostgreSQL/Neon и локальный SQLite;
- Vercel Function + Blob;
- Telegram webhook и scheduled reminders;
- AI orchestration с grounded tools;
- GitHub Actions, regression checks и security controls.

## Перед демонстрацией

- проверить `/api/health`;
- открыть сайт в приватной вкладке;
- убедиться, что есть услуги, мастера и будущие слоты;
- проверить три демонстрационных входа;
- проверить Telegram-бота;
- не показывать Vercel Environment Variables, `.env`, токены и данные настоящих клиентов;
- подготовить резервную запись экрана на случай нестабильного интернета.
