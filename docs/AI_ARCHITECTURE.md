# AI-помощник по записи

AI-помощник превращает свободный запрос клиента в безопасный сценарий записи: услуга → подходящий мастер → реальный свободный слот → явное подтверждение.

## Архитектура

```text
Клиентский чат
  → POST /api/ai/chat
    → OpenAI Responses API или локальный demo engine
      → list_services
      → list_masters(service_id)
      → find_available_slots(service_id, master_id, dates)
  → карточка подтверждения в браузере
    → POST /api/ai/book (confirmed: true)
      → обычный bookingService с повторной проверкой слота
```

Модель не имеет доступа к SQLite и не может самостоятельно создавать записи. Она получает только минимальные бизнес-данные через функции с жёсткими JSON-схемами. Телефон и имя вводятся в отдельной форме уже после выбора слота и не попадают в историю чата.

## Режимы

- `AI_PROVIDER=auto`: сначала используется Gemini, затем OpenAI; без ключей включается резервный пошаговый подбор.
- `AI_PROVIDER=gemini`: используется Gemini при наличии `GEMINI_API_KEY`.
- `AI_PROVIDER=demo`: всегда используется детерминированный резервный режим, который не называется AI в интерфейсе.
- При ошибке или таймауте OpenAI запрос автоматически обрабатывается demo engine.

Резервный движок читает актуальные услуги, связи мастер–услуга и свободные слоты, но является пошаговым интерфейсом, а не языковой моделью.

## Безопасность и приватность

- сообщения чата не сохраняются в базе;
- телефон и email маскируются перед внешним запросом;
- для abuse detection передаётся необратимый SHA-256 идентификатор, а не IP;
- включены лимиты по IP, суточный лимит внешней модели и таймаут;
- `store: false` отключает сохранение ответа через API;
- запись требует `confirmed: true` и ещё раз проходит проверку конфликтов;
- в аналитике сохраняются только provider, вызванные инструменты, успех и latency.

## Настройка

Добавьте в `server/.env`:

```env
AI_PROVIDER=auto
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.1-flash-lite
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.4-mini
AI_DAILY_REQUEST_LIMIT=100
AI_TIMEOUT_MS=60000
```

Ключ нельзя помещать в клиентский `.env`, исходный код или GitHub. Без ключа приложение остаётся полностью работоспособным.
