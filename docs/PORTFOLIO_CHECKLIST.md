# План упаковки портфолио на 7 дней

Один сильный production-проект может быть убедительнее нескольких незавершённых, если по нему видно постановку задачи, инженерные решения, проверку качества и понимание ограничений.

Требования Tech Orda зависят от выбранной школы и курса; перед отправкой нужно сверить карточку именно своего курса на [официальной витрине Astana Hub](https://astanahub.com/ru/techorda/).

## День 1 — репозиторий

- [x] Публичная рабочая версия.
- [x] Профессиональный README.
- [x] Case study и архитектура.
- [x] Security policy и проверка секретов.
- [x] CI, dependency audit и Dependabot.
- [ ] Добавить 4–6 чистых скриншотов без интерфейса браузера и личных данных.

## День 2 — демонстрация

- [ ] Подготовить безопасные demo-аккаунты трёх ролей.
- [ ] Записать видео на 2–3 минуты по сценарию из `DEMO_SCRIPT.md`.
- [ ] Показать клиентский путь, AI, Telegram и один административный сценарий.
- [ ] Добавить ссылку на видео в README и резюме.

## День 3 — резюме

- [ ] Имя, город, контакты и ссылки GitHub/LinkedIn/Telegram.
- [ ] Целевая позиция: AI Engineer Intern / Junior AI Engineer.
- [ ] Короткое summary на 3–4 строки.
- [ ] Навыки, подтверждённые именно этим репозиторием.
- [ ] Описание проекта через проблему, действия и результат без выдуманных метрик.
- [ ] Образование, курсы, языки и доступность для обучения.

## День 4 — заявка

- [ ] Объяснить, почему выбран AI Engineering.
- [ ] Показать, что AI в проекте grounded и управляется бизнес-правилами.
- [ ] Назвать пробелы, которые должно закрыть обучение: ML fundamentals, data pipelines, evaluation, MLOps.
- [ ] Связать обучение с понятным следующим продуктовым этапом.

## День 5 — техническая репетиция

- [ ] Пройти demo script без подсказок за 5–7 минут.
- [ ] Быть готовым объяснить схему данных, JWT, CORS, race condition записи и AI fallback.
- [ ] Проверить сайт с телефона и компьютера.
- [ ] Проверить CI, Telegram, health endpoint и будущие слоты.

## День 6 — обратная связь

- [ ] Дать проект одному техническому и одному нетехническому человеку.
- [ ] Записать вопросы, которые возникли без ваших пояснений.
- [ ] Исправить только критичные пробелы презентации, не расширять продукт новыми крупными функциями.

## День 7 — отправка

- [ ] Повторно проверить ссылки в заявке и PDF-резюме.
- [ ] Открыть GitHub и demo в приватной вкладке.
- [ ] Убедиться, что нигде не опубликованы пароли, токены или данные клиентов.
- [ ] Отправить заявку заранее, оставив время на технические проблемы.

## Формулировка проекта для резюме

> Разработал и развернул full-stack платформу онлайн-записи с ролями клиента, мастера и администратора, Telegram-автоматизацией и grounded AI-помощником. Реализовал проверку конфликтов бронирования, PostgreSQL/SQLite data layer, serverless deployment, Blob-хранилище, AI evals и CI regression workflow.

Не добавляйте проценты роста, количество пользователей или коммерческий результат, пока они не подтверждены реальными данными.
